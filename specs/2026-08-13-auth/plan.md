## Group 3 — Server-side auth: signup / login / refresh / me / password-reset endpoints
- [ ] `backend/`: delete the Nest boilerplate unit specs `src/app.controller.spec.ts` and `src/app.service.spec.ts` (they test scaffolding the health controller replaces)
- [ ] `backend/src/users/`: `users.module.ts` + `users.service.ts` (`findByEmail`, `findById`, `create`, `upsertGoogle`) + `users.service.spec.ts` with 4 unit tests (each method: hit/miss)
- [ ] `backend/src/auth/password.service.ts`: bcryptjs `hash` (cost 10) + `verify` + `password.service.spec.ts` with 3 unit tests (roundtrip true, wrong password false, hashes differ per password)
- [ ] `backend/src/auth/reset-token.service.ts`: mint/verify a purpose-scoped JWT (claim `purpose: "password_reset"`, TTL from `RESET_TOKEN_TTL`) + `reset-token.service.spec.ts` with 4 unit tests (mint, valid verify, wrong-purpose rejected, expired rejected)
- [ ] `backend/src/auth/auth.service.ts` + `auth.controller.ts`: endpoints — `POST /auth/signup` {email, password, displayName?} → 201 {user, accessToken, refreshToken} (409 on duplicate email), `POST /auth/login` → 200 same shape (401 on bad credentials), `POST /auth/refresh` {refreshToken} → 200 new pair (rotation, 401 on invalid), `POST /auth/forgot-password` {email} → 202 always (both known and unknown emails, no user enumeration), `POST /auth/reset-password` {token, newPassword} → 200 (401 on invalid/expired token), `GET /auth/me` → 200 user; access token 15m / refresh 30d signed with `JWT_SECRET`
- [ ] `backend/src/auth/`: `jwt.strategy.ts` (passport-jwt from `Authorization: Bearer`) + `jwt-auth.guard.ts` + `jwt.strategy.spec.ts` with 2 unit tests
- [ ] `backend/src/auth/auth.service.spec.ts`: 5 unit tests with a mocked `PrismaService` (test double, test file only) — signup hashes+returns pair, duplicate → conflict, login ok, login wrong → unauthorized, refresh rotates
- [ ] `backend/src/auth/auth.controller.ts`: forgot-password sends email via `resend` SDK (`From: onboarding@resend.dev`, `To: <requested email>`, body contains `https://spotifyclone.auth/reset?token=<token>` link with the reset token); no fallback logging of the token anywhere
- [ ] `backend/test/auth.e2e-spec.ts` (replaces `test/app.e2e-spec.ts`): supertest against the running app with real Supabase, unique emails per run (`e2e-${Date.now()}@test.local`), cleanup after run — exactly 10 tests: (1) signup → 201 with user+tokens, (2) duplicate signup → 409, (3) login → 200 tokens, (4) login wrong password → 401, (5) `/auth/me` with access token → 200, (6) `/auth/me` without token → 401, (7) refresh → 200 new pair and new access token works on `/auth/me`, (8) refresh with garbage → 401, (9) forgot-password → 202 (known and unknown email), (10) reset-password with service-minted token → 200 then login with the new password → 200
- [ ] **Verify**: `npm run test:e2e` → expect `Test Suites: 1 passed, 1 total` and `Tests: 10 passed, 10 total`; also `npm test` → expect `Test Suites: 5 passed, 5 total` and `Tests: 18 passed, 18 total`
